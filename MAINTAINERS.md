described in [GOVERNANCE.md](./GOVERNANCE.md).

This table is empty because the project has just been created and has not yet
had contributors other than its author. Listing names that have not agreed to
the role, or inventing an organisation, would misrepresent who is accountable
for the code — so it stays empty until someone fills it.

If you are opening a pull request and are not sure who should review it, open it
anyway and describe what it changes.

## Adding yourself

Maintainership is proposed by an existing maintainer after sustained
contribution, per [GOVERNANCE.md](./GOVERNANCE.md#becoming-a-maintainer). The
most direct route is contributing a language implementation and then maintaining
it.

When you become a maintainer, add a row here with:

- your name or handle, and a link,
- the area you cover,
- optionally, the time zone you are usually reachable in, which helps people
  understand review latency.
